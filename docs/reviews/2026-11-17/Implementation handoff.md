## First patch in detail · F02 archive keeper protection

**Trace.** In `ArchivePeek.tsx`, the control labelled **Keep folder** explains that the archive can be deleted later. `ArchiveDiffWizard.tsx` offers the same choice. The API saves `"folder"` or `"archive"` keyed by run and path. The staging loop iterates confirmed paths and skips the row when `keeper == "folder"`. The exporter's `load_matches()` starts instead from CSV verdicts and checks for rejection. It can select a protected archive without consulting its keeper. Its generated script embeds concrete paths, so later changes to the UI cannot edit a previously exported script. [Labels](https://github.com/cephyrixzyth/Audiotheca/blob/ee8b368e9bc5d0cbdd00097054c7f8e1ca64e4cb/ui/src/components/ArchivePeek.tsx#L350) · [Wizard choice](https://github.com/cephyrixzyth/Audiotheca/blob/ee8b368e9bc5d0cbdd00097054c7f8e1ca64e4cb/ui/src/components/ArchiveDiffWizard.tsx#L81) · [Preference write](https://github.com/cephyrixzyth/Audiotheca/blob/ee8b368e9bc5d0cbdd00097054c7f8e1ca64e4cb/archive_feedback.py#L253) · [Staging branch](https://github.com/cephyrixzyth/Audiotheca/blob/ee8b368e9bc5d0cbdd00097054c7f8e1ca64e4cb/api/archive_execute.py#L69) · [Generated path list](https://github.com/cephyrixzyth/Audiotheca/blob/ee8b368e9bc5d0cbdd00097054c7f8e1ca64e4cb/gen_archive_delete_candidates.py#L150)

| Input state for the current archive and run | Expected decision and visible result |
|---|---|
| Rejected, under any keeper setting | Exclude from execution. Show the rejection reason when a row is requested explicitly. |
| Keep archive, including after a previous confirmation | Exclude the archive and its parts. Preserve the extracted copy. Clear or invalidate the stale delete confirmation. |
| Keep folder, current verified sibling, no delete confirmation | Display the preference. A review candidate can remain visible. Live execution still needs explicit approval. |
| Keep folder, current verified sibling, confirmed | Preview lists the archive parts and their destinations. Live moves exactly that set to staging. The extracted folder and its bytes survive. |
| Existing run, explicit confirmation, no keeper ever selected | Preserve the documented interpretation of “Confirm delete” as approving the redundant archive, provided the current sibling and inventory can be verified. If the evidence is missing, surface a review-required result. |
| Preference changes after preview, or multipart membership changes | Invalidate the earlier plan. Show which path or decision changed. A newly appearing part must not silently join an already approved batch. |

**Implementation order**

1. Seed a real ZIP and extracted sibling with identical sample bytes. Write an archive-peek CSV for the same stamp. Use lowercase paths to isolate the keeper logic from F08. A separate mixed-case test is required for F08.
2. Make candidate selection honor an explicit keep-archive veto before expanding multipart names. Pass the run stamp and original path when reading feedback. At the feedback write boundary, supersede contradictory confirmation state. Preserve the historical correction log for display.
3. Reuse that decision in the generator. It may continue to identify candidates for *review*. Make the generated executable rows distinguish explicitly approved moves from unapproved candidates. An exported script containing fixed paths should verify its plan revision, or be generated from freshly revalidated approvals at execution time. Mark older exports stale in the migration instructions.
4. Check both API routes and both UI controls. Preserve the JSON fields consumed by the current results panel. In a disposable live-stage test verify source disappearance, staged bytes, surviving folder bytes, part count and exact ledger destinations. Include two unrelated archives with the same basename and a rejected part.
5. Run the three supplied F02 assertions and the repository archive/execute tests. In a throwaway experiment, changing just the staging branch made **both API checks pass and left the generator check failing**. That narrow change is insufficient. The experiment did not qualify live staging or PowerShell execution.

## Next patches for file safety and durable state

### F01 · Reverse moves without losing intervening edits

Read `guarded_move → log_move → commit_move → _load_entries → rollback_batch`, then read `execute_history`. The committed row currently remembers source, destination and directory status. A path existing at the expected location proves only that something occupies it. A prior successful reversal is also invisible to the current folding logic. [Recorded fields](https://github.com/cephyrixzyth/Audiotheca/blob/ee8b368e9bc5d0cbdd00097054c7f8e1ca64e4cb/audiotheca/transaction_ledger.py#L32) · [Reversal](https://github.com/cephyrixzyth/Audiotheca/blob/ee8b368e9bc5d0cbdd00097054c7f8e1ca64e4cb/audiotheca/transaction_ledger.py#L92) · [Existing success test](https://github.com/cephyrixzyth/Audiotheca/blob/ee8b368e9bc5d0cbdd00097054c7f8e1ca64e4cb/tests/test_transaction_ledger.py#L8)

**First slice.** Reject an occupied restore target for files and directories in preview and at execution. Return the conflict per path, leave both contents intact, and make the existing clean round trip pass. Serialize competing operations for the same entries and choose a no-overwrite move primitive appropriate to the filesystem. A separate existence check followed by an overwriting rename still has a race.

**Durable slice.** Add append-only reversal intent and terminal outcome keyed by original entry and batch. On restart fold them before choosing eligible rows. For an old entry with insufficient identity evidence, recognize a conflict or request manual reconciliation. A duplicate rollback request after success should report zero additional moves. Preserve old committed history. A successful move followed by a failed ledger write is an ambiguous state that needs a new disk check before replay.

| Original location | Staged location | Expected handling on undo |
|---|---|---|
| Vacant | Matches the recorded object | Preview eligibility, reverse once, verify recovered object, record reversal. |
| Occupied | Present | Preserve both and report conflict, including if the occupied target is a directory. |
| Present | Vacant | Respect a recorded reversal. With only a pending intent, verify identity and reconcile. |
| Vacant | Vacant, or staged identity changed | Report missing or changed data. Leave the operation open for review. |

**Proof.** Run the three F01 checks. Then add a two-entry batch with one conflict, retry after resolving it, and reopen the ledger in a second process. Also exercise a cross-device failure and a directory tree where child operations were committed individually. Never infer that every row succeeded from a batch returning `ok: true`.

### F03 · Revalidate a duplicate group at execute time

Read `build_plan_from_decisions`, `add_rejection`, the CLI's `_cmd_execute`, and `stage_approved_duplicates`. An approval is an earlier statement of intent. The same library may have been edited in the meantime. The planner's initial membership check cannot establish that the keeper still exists at execution time. **Patch contract.** Validate the current run, library identity, keeper, rejection state and all members before moving any member of that group. Record sufficient identity at approval to distinguish a replacement at the same path. Check the full plan for keeper/other-group overlap, case aliases and directory ancestry. An inexpensive signature may reject a changed file quickly. Where equality justifies a removal, require content evidence appropriate to the whole object. Preserve version-coexist and reference-library decisions as distinct review cases.

**State changes.** Saving a new choice, clearing a choice or rejecting a group invalidates the old executable revision. At live execute, compare the revision immediately before mutation and record the actual per-member outcome. A group with a missing keeper has zero eligible discards. A failure during the third move retains receipts for the first two and reports the third as unresolved. Replay must consult those receipts.

**Proof.** Use the provided valid/missing/rejected cases. Add keeper replaced at the same name, keeper inside a discard directory, overlapping groups, old imported plan with missing identity and a single group with two discards where one is unavailable.
